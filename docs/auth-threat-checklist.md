# Auth threat checklist (`TSC-AUTH-003`)

A working checklist of authentication/session threats, what mitigates each one
in this codebase, and how that mitigation is verified (backend/frontend
targeted tests, and/or the full-stack Playwright suite in
[`frontend/e2e-auth/`](../frontend/e2e-auth)). Used to confirm the auth
vertical slice (`TSC-AUTH-001` + `TSC-AUTH-002`) has no outstanding gap before
sign-off, per spec §7.1/§9.4/§10.2.

| # | Threat | Mitigation | Verified by |
| - | ------ | ---------- | ----------- |
| 1 | Password brute-forcing / credential stuffing | Argon2id password hashing ([`security.py`](../backend/app/core/security.py)); per-IP sliding-window rate limit on `/auth/register`, `/auth/login`, `/auth/refresh` (default 10/min, [`rate_limit.py`](../backend/app/core/rate_limit.py)). | `backend/tests/test_auth.py::test_login_is_rate_limited_per_ip`. |
| 2 | User enumeration via login/registration errors | Login returns the identical generic `"Invalid email or password."` for both an unknown email and a wrong password (constant-time dummy hash comparison so the code path timing doesn't leak which case occurred either); registration duplicate errors are scoped to the caller's *own* attempt, which is not an enumeration surface. | `backend/tests/test_auth.py::test_login_rejects_wrong_password_with_generic_message`, `::test_login_rejects_unknown_email_with_the_same_generic_message`; `frontend/e2e-auth/auth-flow.spec.ts` → "Invalid credentials". |
| 3 | Access token theft via XSS / persistent storage | Access token lives only in the in-memory Zustand store, never `localStorage`/`sessionStorage`/IndexedDB/a JS-readable cookie ([`auth-store.ts`](../frontend/src/stores/auth-store.ts)); React auto-escapes all rendered content (no `dangerouslySetInnerHTML` for user content). | Vitest storage-inspection tests (`frontend/tests/routes/auth-flow.test.tsx`); the auto-asserting `test` fixture in `frontend/e2e-auth/fixtures.ts` checks `localStorage`/`sessionStorage`/`document.cookie` after every E2E test. |
| 4 | Refresh token theft / CSRF via the refresh cookie | Refresh cookie is `httpOnly` + `Secure` (non-local) + `SameSite=Strict`, scoped to `path=/api/v1/auth` ([`routers/auth.py`](../backend/app/routers/auth.py)); state-changing requests authenticate via the `Bearer` access token, not a cookie, so a cross-site form POST can't act as the user. | `backend/tests/test_auth.py::test_login_returns_access_token_and_sets_refresh_cookie`, `::test_login_sets_a_secure_cookie_in_production`. |
| 5 | Refresh token replay (stolen/leaked cookie reused after legitimate rotation) | Every `/auth/refresh` rotates the refresh token and revokes the old one; presenting an already-revoked token is detected as reuse and revokes the *entire* token family, forcing re-login everywhere ([`services/auth.py::rotate_refresh_token`](../backend/app/services/auth.py)). | `backend/tests/test_auth.py::test_replayed_refresh_token_revokes_the_whole_family`; `frontend/e2e-auth/auth-flow.spec.ts` → "Revoked refresh token (reuse detection)". |
| 6 | Expired/invalidated access token breaking the session instead of recovering | The API client's single-flight `401` → `refresh` → retry-once logic ([`client.ts`](../frontend/src/api/client.ts)) transparently recovers without the user re-authenticating or seeing an error, and without a redirect loop on genuine failure. | Vitest concurrent-401 tests (`frontend/tests/routes/auth-flow.test.tsx`); `frontend/e2e-auth/auth-flow.spec.ts` → "Expired access token recovery" (against the real backend). |
| 7 | JWT algorithm confusion / `alg: none` | `jwt.decode(..., algorithms=[settings.jwt_algorithm])` pins the accepted algorithm explicitly (HS256); a token minted with a different `type` claim (e.g. a refresh token forged as a JWT) is rejected. | `backend/tests/core/test_security.py`; `backend/tests/test_auth.py::test_me_rejects_a_malformed_token`. |
| 8 | Refresh-token hash brute-forcing from a database leak | `refresh_tokens.token_hash` is an HMAC keyed with `jwt_secret_key`, not a bare hash, so a DB leak alone can't offline-confirm a guessed raw token without also knowing the server secret. | `backend/tests/core/test_security.py` (hash determinism/keying); code review of [`hash_refresh_token`](../backend/app/core/security.py). |
| 9 | Secrets/passwords/tokens leaking into logs or responses | `UserPublic` never includes `password_hash`; structured logging never logs request bodies or raw tokens; the standard error envelope never echoes a raw exception message for 500s. | `backend/tests/test_auth.py::test_register_returns_public_user_shape_without_password`; `backend/tests/core/test_errors_backstop.py`. |
| 10 | Missing transport/browser hardening (clickjacking, MIME sniffing, referrer leakage) | `Content-Security-Policy: default-src 'self'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `Referrer-Policy: strict-origin-when-cross-origin`, `X-Frame-Options: DENY` always; HSTS added in production only (so local/CI HTTP isn't broken) ([`middleware.py`](../backend/app/core/middleware.py)). | `backend/tests/test_security_headers.py`. |
| 11 | Cross-origin credentialed requests from an untrusted origin | CORS restricted to the configured allow-list (`CORS_ALLOWED_ORIGINS`, default `http://localhost:5173`) with credentials support, not a wildcard. | `backend/tests/test_cors.py`. |
| 12 | Redirect loop on a broken/expired session | `expireSession()` only flags `sessionExpired` when there *was* a session to lose, and the login screen acknowledges the flag exactly once on mount — back/forward navigation can't re-trigger a toast/redirect cycle. | Vitest routing tests (`frontend/tests/routes/auth-flow.test.tsx`); `frontend/e2e-auth/fixtures.ts`'s console/request assertions (a loop would surface as excess console/network activity). |
| 13 | Flaky/non-reproducible auth E2E coverage masking a real regression | The auth E2E suite runs serialized (`workers: 1`), with zero retries even in CI, against the real containerized stack, and is required to pass three consecutive times before sign-off. | `.github/workflows/ci.yml` → `auth-e2e` job (3 consecutive `npm run e2e:auth` runs); `make e2e-auth` locally. |

## Not yet in scope (tracked for later tasks)

- **WebSocket auth** (short-lived token via query param/subprotocol) lands
  with `TSC-CORE-*`/`TSC-NOTIF-*` — no WS endpoint exists yet to test.
- **Account lockout / anomaly detection** beyond per-IP rate limiting is not
  in the v1 spec and is out of scope here.
